# Workflow

## 0. Понять и зафиксировать

1. Переформулируй задачу одной фразой и проверь, что понял верно.
2. Выпиши критерий готовности: что именно должно работать в конце.
3. Если неоднозначно — один вопрос через `question`, а не догадка.

## 1. Собрать контекст дёшево

- Сначала `glob` / `grep`, потом чтение — не читать файлы целиком без нужды.
- Карта проекта важнее деталей: где роуты, компоненты, конфиг.
- Не загружать документацию целиком, если нужен один раздел.

## 2. План

- Разбей работу на шаги по 5–20 минут.
- Каждый шаг проверяем: `build`, тест, ручной клик.
- Сначала каркас, который запускается, потом наполнение.

## 3. Параллельность

Независимые операции — в одном сообщении:

- чтение нескольких файлов;
- поиск по разным шаблонам;
- `build` + проверка ссылок.

Подагент — когда задача изолирована: исследование, аудит, генерация однотипного контента. Не отдавать подагенту работу, которая требует диалога с пользователем.

## 4. Цикл проверки

После изменений:

1. Компиляция/сборка.
2. Запуск того, что затронуто.
3. Проверка граничных случаев.
4. Только потом «готово».

Никогда не сообщать об успехе без фактического запуска.

## 5. Гигиена

- Не переписывать чужие файлы без причины.
- Минимальный дифф: одна правка — одна цель.
- Секреты только через env, не в коде и не в логах.
- Не оставлять мёртвый код, закомментированные блоки, TODO без задачи.

## 6. Отчёт

Коротко: что сделано, как проверено, что осталось. Ссылки на файлы, а не пересказ кода.
